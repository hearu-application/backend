# 문서 드리프트 감사

`CLAUDE.md` · `.claude/rules/*.md` · `.claude/skills/*/SKILL.md` · `docs/*.md`가 현재 코드와
어긋난 곳을 찾는다. **고치지 말고 보고만 한다.**

## 절차

1. **범위 확인** — 위 문서들과, 마지막 감사 이후 바뀐 코드를 본다.
   기준을 모르면 `git log --oneline -30`으로 최근 변경을 훑는다.

2. **주장 대조** — 문서가 말하는 것을 코드에서 실제로 확인한다. 특히:
   - **숫자** — 스레드 풀 크기, 재시도 횟수, 타임아웃, 제한 건수, cron 표현식
   - **이름** — 클래스·메서드·빈·설정 키가 실제로 존재하는지
   - **흐름** — 호출 방향, 이벤트 발행/구독, 트랜잭션 경계, 필터 순서
   - **상태 전이** — enum 값과 전이를 막는 조건
   - **링크** — 가리키는 파일이 존재하는지

3. **소유권 위반 탐지** — `.claude/rules/documentation.md`의 소유자 표를 기준으로,
   한 사실이 여러 파일에 근거·절차·숫자까지 복제된 곳을 찾는다.

4. **해결된 미결 과제** — `docs/plan/*.md`의 항목이 이미 코드에 반영됐는지 확인한다.

## 보고 형식

심각도 순으로. 각 항목은 **문서 위치 / 문서의 주장 / 코드의 실제 / 근거 파일**.

| 심각도 | 기준 |
|---|---|
| 높음 | 문서를 믿고 작업하면 코드가 깨지거나 잘못된 구조가 된다 |
| 중간 | 사실이 틀렸지만 즉시 해를 끼치지는 않는다 (숫자·이름 불일치) |
| 낮음 | 중복·죽은 링크·해결된 TODO 잔존 |

## 오탐 억제

다음은 드리프트로 보고하지 않는다:

- 동작이 바뀌지 않은 내부 리팩터링·이름 변경
- 문서가 **의도적으로** 요약한 것 (소유자 표상 "한 줄 요약"이 허용된 위치)
- 로그 문구·주석·DTO 필드처럼 문서가 애초에 다루지 않는 세부

**추측하지 말 것.** 코드를 열어 확인하지 못한 항목은 보고에서 빼고, 확인 못 한 이유를 따로 적는다.
그럴듯한 오보는 인정된 드리프트보다 나쁘다 — 사람이 승인해서 문서에 반영되면 틀린 사실이
"검증된 것"으로 승격되기 때문이다.
