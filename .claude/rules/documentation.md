# 문서 관리 규칙

문서를 고칠 때 지킨다. **"어느 파일에 쓸 것인가"를 매번 다시 판단하지 않기 위한 규칙이다.**

## 사실의 소유자

한 사실은 한 파일이 소유한다. 다른 파일은 **링크하거나 한 줄로 요약**하고, 근거·절차·숫자를 옮겨 적지 않는다.

| 주제 | 소유 파일 | 다른 곳에서 허용되는 것 |
|---|---|---|
| 런타임 흐름, 시퀀스, 상태 기계, API 표, 설정값(풀 크기·재시도 횟수·제한 건수) | `docs/architecture.md` | 흐름 요약, 설계 결정 한 줄 |
| 아키텍처 설계 결정(잘 안 변하는 것) | `.claude/skills/architecture/SKILL.md` | — |
| 로그 레벨 기준, MDC, 마스킹, 로그 태그 | `.claude/rules/logging.md` | "민감정보는 `LogMasker`로" 정도 |
| Flyway 절차와 불변식 | `.claude/rules/db-migration.md` | "적용된 파일 수정 금지" 한 줄 |
| 엔티티·DTO·서비스·컨트롤러 규칙, 기간 조회 | `.claude/rules/coding-style.md` | 위반 시 조용히 깨지는 것만 한 줄 |
| 테스트 규칙 | `.claude/rules/testing.md` | — |
| 빌드·실행, 환경변수, 커밋 컨벤션, **문서 갱신 조건** | `CLAUDE.md` | — |
| 미결 과제·개선 계획 | `docs/plan/*.md` | — |

## 복제 판단 기준

중복이 위험한 건 길이가 아니라 **변동성**이다.

- ✅ **복제해도 되는 것** — 한 줄 경고, 잘 변하지 않는 원칙
  (예: "적용된 마이그레이션은 수정하지 않는다")
- ❌ **복제하면 안 되는 것** — 근거, 절차, 숫자, 코드 예시, 목록
  (예: 재시도 대상 예외 목록, 스레드 풀 크기, 하루 제한 건수)

숫자를 다른 파일에 옮겨 적었다면 그 순간부터 두 곳이 어긋나기 시작한다고 본다.

## 미결 과제는 참조 문서에 쓰지 않는다

`docs/architecture.md`·rules·skill에는 **현재 상태만** 쓴다. TODO·개선 계획은 `docs/plan/`이 갖는다.
해결된 뒤에도 남아서 문서 전체의 신뢰를 깎기 때문이다.

## 코드 참조는 이름으로 한다

`AsyncConfig.java:29` 같은 줄 번호는 다음 커밋에 틀린다. 클래스·메서드 이름으로 참조한다 —
리네임되면 grep으로 잡힌다.

## 드리프트 점검

필요할 때 `/docs-audit`을 돌려 코드와 문서의 불일치를 찾는다(자동화하지 않는다).
문서를 쓰는 것보다 **검증하는 것**이 에이전트가 잘하는 일이다.

문서의 특정 주장 하나가 의심스러울 때는 `/verify`가 더 싸다 — 전체 감사 대신 그 명제만 확인한다.
